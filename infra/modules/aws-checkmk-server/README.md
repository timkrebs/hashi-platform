# aws-checkmk-server

Runs [Checkmk](https://checkmk.com) Raw Edition on a single EC2 instance in a
public subnet, on the company's hardened Ubuntu 24.04 base image
(`hc-base-ubuntu-2404-amd64-*` from the ami-prod account). The package is
downloaded and checksum-verified at first boot, the site is created
non-interactively, and the web interface is served over HTTPS with a self-signed
certificate.

The initial `cmkadmin` password is generated by `random_password`, stored as an
SSM `SecureString`, and read by the instance from SSM at boot through its
instance profile — it never appears in user data. Shell access is through SSM
Session Manager, so there is no key pair and port 22 is never opened.

Ubuntu 24.04 is required rather than merely preferred: Checkmk publishes no
build for 26.04, so the hardened 26.04 family cannot be used here. The
`-eks-` variants of the hardened image are rejected by validation — they carry
kubelet and belong on EKS node groups, not on a standalone server.

Because the image is hardened, the bootstrap opens 80 and 443 in `ufw` when a
host firewall is active, and treats a missing `snapd` as a warning rather than a
failure.

## Defaults worth knowing

- **`t3.medium` is a ceiling, not a preference.** The repository's
  `restrict-compute-size` Sentinel policy rejects anything larger than `medium`.
  4 GB of RAM suits a handful of monitored hosts; it will swap long before 100.
- **The interface is open to `0.0.0.0/0`** and the certificate is self-signed.
  Narrow `allowed_cidr_blocks` wherever you can.
- **Editing the bootstrap replaces the instance.** `user_data_replace_on_change`
  is set, because the script is only meaningful on a fresh boot. Every version
  bump therefore destroys the server and all monitoring history with it.

## Usage

```hcl
module "checkmk" {
  source = "../../../modules/aws-checkmk-server"

  name      = "hashi-platform-dev-checkmk"
  region    = var.region
  vpc_id    = data.terraform_remote_state.cluster.outputs.vpc_id
  subnet_id = data.terraform_remote_state.cluster.outputs.public_subnet_ids[0]

  allowed_cidr_blocks = ["203.0.113.0/24"] # narrower than the default

  tags = local.common_tags
}
```

The subnet must be public: the bootstrap downloads a 284 MB package and the
interface is reached over the elastic IP.

## First login

```sh
terraform output -raw checkmk_url                     # https://<eip>/cmk/
eval "$(terraform output -raw checkmk_admin_password_command)"
```

Browse to the URL, accept the certificate warning, and log in as `cmkadmin`.
The SSM value is the *initial* credential only: once you change the password in
the interface, SSM is stale and Terraform will not reconcile it.

## Verifying the bootstrap

`terraform apply` returns as soon as the instance launches — it does **not**
wait for Checkmk. Allow four to six minutes, then:

```sh
aws ssm start-session --target "$(terraform output -raw checkmk_instance_id)"

sudo cloud-init status --long
sudo tail -100 /var/log/cloud-init-output.log
ls -l /var/lib/checkmk-bootstrap.done   # exists only on success
sudo omd status cmk
systemctl status apache2
```

## Upgrading Checkmk

1. Pick the new version and confirm it has a `noble` build.
2. Read the checksum from the sidecar the project publishes next to it:
   ```sh
   curl -fsSL https://download.checkmk.com/checkmk/<version>/check-mk-raw-<version>_0.noble_amd64.deb.hash
   ```
3. Set `package_url` and `package_sha256` together.

The instance never fetches that sidecar itself: whoever can serve a bad package
can serve a matching hash, so the checksum is pinned in the repository where it
is reviewed. Bumping the version replaces the instance.

## Security

- The interface is internet-facing by default and the certificate is
  self-signed, so every user is trained to click through a warning. Narrowing
  `allowed_cidr_blocks`, or fronting the site with a real certificate, is worth
  doing before this is more than a sandbox.
- HSTS is deliberately **not** set. With a self-signed certificate it would pin
  browsers to a broken HTTPS for that address permanently.
- `omd create` takes the password as an argument, so it is briefly visible in
  `ps` on the host during the first boot. There is no non-interactive
  alternative in Checkmk 2.4 (`cmk-passwd` requires a TTY).
- The generated password is in Terraform state, encrypted at rest. Anyone who
  can read state can read it.
- The package is verified against a pinned SHA256. For belt and braces you can
  additionally verify the signature with Checkmk's
  [public key](https://download.checkmk.com/checkmk/Check_MK-pubkey.gpg) and
  `dpkg-sig --verify`.

## Inputs

| Name | Description | Type | Default | Required |
|---|---|---|---|:--:|
| name | Name of the server; prefixes the security group, IAM role, instance profile and SSM parameter. | `string` | n/a | yes |
| region | AWS region. Used for the SSM lookup at boot and to scope the `kms:Decrypt` grant. | `string` | n/a | yes |
| vpc_id | VPC the security group is created in. | `string` | n/a | yes |
| subnet_id | Public subnet the instance is launched into. | `string` | n/a | yes |
| instance_type | EC2 instance type. Capped at `medium` by policy. | `string` | `"t3.medium"` | no |
| root_volume_size | Size of the encrypted gp3 root volume in GiB. | `number` | `30` | no |
| allowed_cidr_blocks | CIDR blocks allowed to reach the interface. | `list(string)` | `["0.0.0.0/0"]` | no |
| site_name | Name of the OMD site; the interface is served under `/<site_name>/`. | `string` | `"cmk"` | no |
| package_url | Download URL of the Checkmk Raw `.deb`. Must be a `noble` build. | `string` | `2.4.0p36` | no |
| package_sha256 | Pinned SHA256 of that package. | `string` | `8208d6a1…` | no |
| ami_owner | Account publishing the hardened image. | `string` | `"888995627335"` | no |
| ami_name_prefix | Name prefix of the hardened image, without the build timestamp. | `string` | `"hc-base-ubuntu-2404-amd64"` | no |
| ami_id | Pin an AMI instead of looking up the newest hardened image. | `string` | `null` | no |
| admin_password_length | Length of the generated `cmkadmin` password. | `number` | `24` | no |
| tags | Tags applied to every resource. `Environment`, `Project` and `ManagedBy` are mandatory. | `map(string)` | `{}` | no |

## Outputs

| Name | Description |
|---|---|
| instance_id | ID of the Checkmk instance. |
| ami_id | AMI the instance was launched from. |
| private_ip | Private address inside the VPC. |
| public_ip | Elastic IP, stable across stop and start. |
| url | URL of the web interface. |
| site_name | Name of the OMD site. |
| security_group_id | Security group attached to the instance. |
| iam_role_arn | ARN of the instance role. |
| iam_role_name | Name of the instance role. |
| admin_password_parameter_name | SSM parameter holding the initial password. |
| admin_password_parameter_arn | ARN of that parameter. |
| admin_password_command | Command that prints the initial password. |
| session_manager_command | Command that opens a shell through Session Manager. |

The password itself is not an output: it would surface in `terraform output` and
in the HCP Terraform run UI. The command above leaves an audit trail instead.

## Tests

Unit tests run in plan mode with mocked providers and the AMI, partition,
parameter ARN and elastic IP replaced by fixed values, so they need no AWS
credentials:

```sh
terraform init -backend=false
terraform test
```
